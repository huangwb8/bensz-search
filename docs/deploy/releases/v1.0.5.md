## 升级与恢复

1.0.5 有 SQLite 增量迁移。上线前保留旧镜像、Compose、匹配环境配置和每个 SQLite 的一致快照；旧代码不可直接使用迁移后的库。回退时停止搜索服务，另备份升级后的新写入，恢复升级前所有数据库和匹配私有配置，再选择旧镜像。不得在日常维护中执行 `down -v`。

仓库服务器 Compose 没有新的网络或挂载偏好变更；沿用 `/docker/bensz-search`、项目内数据 bind mounts、外部 `npm_default` 网络和仅 expose 的方式。发布操作只拉取并重建 `search` 服务。

服务器沿用空的 `BENSZ_SEARCH_IMAGE` 覆盖值，按既有偏好使用 `latest`。Compose 与 `.env` 哈希不变，SearXNG 的容器 ID、镜像 ID 和启动时间不变。升级前在服务器私有 `.secrets/release-v1.0.5-20261007/` 备份配置及一个 SQLite 数据库，使用 SQLite backup 取得一致快照，副本完整性为 `ok`。旧镜像保留为本地 `huangwb8/bensz-search:pre-v1.0.5-20261007`，不上传该标签。

```bash
docker compose -f docker-compose.yml pull search
docker compose -f docker-compose.yml up -d --no-deps --wait --wait-timeout 180 search
```

初次服务器拉取遇到 SSH 中断，重新连接确认旧容器仍健康，继续同一升级后成功。Docker Hub 首次推送遇到认证连接 EOF，原发布重试成功；没有更改代理配置或重启其他服务。
