# v1.0.4 镜像与服务器验收

## 发布范围

2026-10-07，按指定版本把 v1.0.3 之后全部提交及工作区更新统一交付为 v1.0.4。包版本唯一源为 `pyproject.toml`；upstream 仍为锁文件固定的 LiteLLM 1.103.2 发行包，未修改 upstream 源码，未取得对应 upstream Git commit。

新增原生 `bensz_search` 搜索源，支持实例递归组合：后台配置远端实例与访问密钥，显式、auto、planned 与 MCP 共用执行链，提供循环检测、层数限制、剩余 deadline、互不重叠的调用额度与子树费用估算；远端先验证联邦支持，不跟随重定向，保留叶子来源与实例路径。源码边界与用法见[实例组合说明](../../smart-search-router/federated-search.md)与[验证记录](../../smart-search-router/federated-search-verification.md)。

随版本交付：Serper 额度耗尽识别为 `quota` 故障并恢复自动 fallback；修复共用搜索执行器嵌套请求取消时未读取原 gather 异常；正式依赖锁文件迁至 `.bensz-api/uv.lock` 并继续纳入 Git，Docker 构建入口经 `scripts/uv.sh` 适配。开发阶段临时使用的 1.1.0 未单独发布。

构建命令：

```bash
docker buildx build --builder desktop-linux --platform linux/amd64 \
  --provenance=false --sbom=false --load \
  -f docs/deploy/Dockerfile \
  -t huangwb8/bensz-search:1.0.4 -t huangwb8/bensz-search:latest .
docker push huangwb8/bensz-search:1.0.4
docker push huangwb8/bensz-search:latest
```

构建器名称属于本次环境，其他环境使用可用构建器；保留单架构、关闭 attestation 并直接推送单个镜像的约束。镜像导入 smoke 检查确认安装版本为 1.0.4。

## 服务器上线

部署目录 `/docker/bensz-search`。服务器 Compose 与 `.env` 未改变：仓库 `docs/deploy` 本次的锁文件迁移在镜像内生效，新增的 `BENSZ_SEARCH_UPSTREAM_*` 变量为可选首次导入项，服务器作为独立实例不配置。上线前在私有 `.secrets/release-v1.0.4-20261007/` 备份 Compose、环境配置与两个 SQLite 数据库文件级快照，副本 `integrity_check` 均为 `ok`；旧镜像保留为本地 `huangwb8/bensz-search:pre-v1.0.4-20261007`，不上传该回滚标签。

服务器 `BENSZ_SEARCH_IMAGE` 为空，按既有偏好使用 `latest`，只拉取并重建 `search` 服务：

```bash
docker compose -f docker-compose.yml pull search
docker compose -f docker-compose.yml up -d --no-deps --wait search
```

验证搜索容器 `healthy`、安装包 1.0.4、运行镜像 digest 与推送一致且为 `linux/amd64`、使用项目内数据 bind mount、没有宿主机端口映射。Compose 与 `.env` 字节未改变；未操作其他服务镜像，本项目 SearXNG 容器保持运行。

需要回滚时，沿用匹配的私有配置，仅切换搜索镜像：

```bash
BENSZ_SEARCH_IMAGE=huangwb8/bensz-search:pre-v1.0.4-20261007 docker compose -f docker-compose.yml up -d --no-deps --pull never --wait search
```

本版本未修改数据库 schema，不需要恢复旧数据库；如果另有数据恢复需求，先备份上线后的新写入，再参照[服务器恢复说明](../server-deployment.md#迁移与恢复)执行。本次保留回滚资源，未执行实际回滚。
