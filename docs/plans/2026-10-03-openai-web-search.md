# OpenAI 网页搜索接入计划

## 通俗解释：究竟发生了什么

用户希望把 OpenAI 的网页搜索加入已有搜索服务。例如搜索一项技术的最新资料时，目前只能选择 Exa、Brave 等来源；完成后可在后台添加 OpenAI，直接调用它，也可让自动路由选择它或与其他来源融合。

## 专业判断：问题在哪里

当前锁定 LiteLLM 1.103.2 的 SearchProviders 不含 OpenAI，但已提供 `litellm.aresponses`。OpenAI 的 `web_search` 是 Responses API 内置工具，返回回答、引用及来源，需要转换为现有 SearchResponse。官方文档已读取，支持强制搜索、域名过滤、地区和来源列表。

## 要达到什么目标

后台可以保存、测试、启停 OpenAI 配置；四种原生搜索路径及自动路由可使用该配置，保留鉴权、结果结构、预算估算、超时和 fallback。不会修改安装的 LiteLLM 源码。

## 改进方向

增加项目专用适配层，通过 LiteLLM Responses 调用搜索，从实际引用和 sources 提取链接；不解析模型自行写出的 URL，不虚构网页日期和正文。后台保存模型、上下文大小和输出上限，凭据继续加密保存。相同 OpenAI 配置使用同一来源族，未知底层来源不宣称独立。

## 实施范围与顺序

1. 记录调用链审计与官方协议，增加配置受控的 OpenAI 适配器。
2. 接入原生入口、自动路由和后台，补充启动配置与文档。
3. 验证真实 Responses 协议的模拟 HTTP、鉴权、参数保护、去重、失败分类及 fallback；同步版本、变更记录与 BAC。

## 如何确认完成

既有 provider 测试与路由 benchmark 通过；新增测试覆盖配置持久化、热更新、域名/地区过滤、来源转换、空结果、错误、超时及显式和自动搜索。使用模拟凭据，不产生真实付费调用；真实 OpenAI 可用性以运营者配置后后台测试为准。

## 风险与待确认事项

OpenAI 检索含工具及模型 token 费用，预算是可配置估算；结果数量为上限，无法保证返回指定数量。来源缺少日期时严格时效过滤会剔除它。主 BAC 在任务开始前曾有根哈希冲突且拒绝追加，初期贡献暂存独立账本；交付前沿用主账本初始身份并披露当前上下文哈希，补充需求与交付汇总。后续账本整理已将阶段性完整历史归入 [唯一贡献账本](../contribution.bac)，删除独立文件，原有历史保持不变。
