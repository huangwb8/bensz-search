# SearXNG 默认搜索源扩充

## 通俗解释：究竟发生了什么

默认搜索配置只查 GitHub 和 PubMed。例如查询旅游信息时，系统仍会去代码库和医学文献找答案。加入网页、百科和新闻搜索源后，普通问题可以搜索网页，代码和论文问题仍优先使用对应的专业来源。

## 专业判断：问题在哪里

部署环境示例和初始化脚本将 `SEARXNG_ENGINES` 固定为 `github,pubmed`。后台首次导入后保存在数据库，后续更改环境变量不会覆盖已有配置。LiteLLM 1.103.2 的 SearXNG adapter 已支持逗号分隔的任意实例引擎，不需增加 provider adapter。

## 要达到什么目标

默认配置包含 Google、Bing、DuckDuckGo、Brave、百度、Wikipedia、GitHub、Stack Overflow、PubMed、arXiv 和 Google News。管理员可以便捷地将常用列表填入已有配置，实际查询继续受实例启用情况、网络和外部限流影响。

## 改进方向

- 统一应用默认值和部署示例，提供独立 SearXNG 设置模板，确保新增引擎也在实例中启用。
- 自动路由按已配置的网页、学术、代码和新闻引擎筛选，避免普通查询被专业来源占满。
- 后台增加填入常用引擎入口与留空说明；保留管理员自定义列表和明确留空使用实例默认的行为。

## 实施范围与顺序

1. 核查配置导入、持久化、路由与 LiteLLM 参数透传，记录源码依据。
2. 更新应用默认配置、后台和部署模板，补充现有实例的更新说明。
3. 验证首次导入、显式留空、自定义列表保存、按意图选择和原生搜索兼容，并追加贡献记录。

## 如何确认完成

默认列表覆盖常用网页和专业来源；后台保存后即时进入运行配置；自动查询使用对应引擎子集；已有自定义配置在重启后保持一致。测试区分模拟调用与真实外部检索。

## 风险与待确认事项

引擎存在或启用不代表实际检索成功，Google/Bing 等可能受到 CAPTCHA 或限流。当前工作在本地项目完成；线上已有数据库需要在后台明确保存新增列表，并启用实例中的对应引擎。
